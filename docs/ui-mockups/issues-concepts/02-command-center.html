ROOT CAUSE ANALYSIS
CoreDNS pods are crash-looping due to a ConfigMap misconfiguration introduced in the last deployment. The forward plugin is pointing to an unreachable upstream resolver at 10.96.0.20:53, causing all DNS queries to time out.

IMPACT
All service-to-service DNS resolution is failing. Any pod that relies on Kubernetes service discovery (virtually all workloads) cannot establish connections. HTTP 502/503 errors are cascading through the cluster.
KUBECTL COMMANDS
$ kubectl logs -n kube-system \ deploy/coredns --tail=20 [ERROR] plugin/errors: 2 SERVFAIL dns.google. AAAA: unreachable upstream: 10.96.0.20:53 $ kubectl rollout restart \ deploy/coredns -n kube-system
AI FIX SUGGESTION
Revert the CoreDNS ConfigMap to the last known-good version, then restart the deployment. Check the Corefile forward directive — it should point to 8.8.8.8 or your internal resolver, not the cluster IP.
