# hetu METL observability — raw Grafana manifests

Self-service, **kubectl-appliable** Grafana datasources and dashboards for the
hetu cluster-health platform, organised around the four **METL** pillars
(**M**etrics, **E**vents, **T**races, **L**ogs).

These are plain ConfigMaps — no Helm required. They are the standalone twin of
the Helm chart templates under `deploy/helm/hetu/templates/monitoring/`; keep
the two in sync if you edit one.

All dashboards land in a **single Grafana folder named `hetu`** (annotation
`grafana_folder: "hetu"`); the `hetu/` and `metl/` subfolders below are just
repo organisation.

```
grafana/
├── contract.yaml                # <<< per-environment endpoints you fill/deliver
├── render.sh                    # contract.yaml + *.tmpl  ->  datasources/*.yaml
├── datasources/                 # grafana_datasource: "1"
│   ├── prometheus.yaml.tmpl     # template (edit this, not the .yaml)
│   ├── prometheus.yaml          # GENERATED by render.sh — uid prometheus (isDefault)
│   ├── loki.yaml.tmpl
│   ├── loki.yaml                # GENERATED — uid loki (derivedFields trace_id → Tempo)
│   ├── tempo.yaml.tmpl
│   └── tempo.yaml               # GENERATED — uid tempo (tracesToLogs/Metrics wired)
├── dashboards/                  # all → grafana_folder: "hetu"
│   ├── hetu/                    # existing app dashboards
│   │   ├── hetu-cluster-intel.yaml
│   │   ├── hetu-ollama.yaml
│   │   └── hetu-llm-traces.yaml
│   └── metl/                    # the four METL pillar overviews
│       ├── metl-metrics.yaml    # cluster CPU / mem / pods (Prometheus)
│       ├── metl-logs.yaml       # log volume + error rate by namespace (Loki)
│       ├── metl-traces.yaml     # request rate / latency p95·p99 / error rate (Prometheus + Tempo)
│       └── metl-events.yaml     # warning/normal event rate (kube_event / cluster_intel_*)
├── kustomization.yaml
└── README.md
```

## The environment contract

`contract.yaml` is the **only** file with cluster-specific endpoints (Loki,
Prometheus, Tempo URLs, namespace, datasource UIDs, folder). Deliver/fill it per
cluster, then regenerate the datasource manifests:

```bash
# 1) edit contract.yaml (especially endpoints.lokiUrl)
# 2) regenerate datasources/*.yaml from the templates
./render.sh                 # or: ./render.sh /path/to/delivered-contract.yaml
# 3) apply
kubectl apply -k .
```

`render.sh` substitutes only the contract's named tokens and leaves Grafana's
own `${__value.raw}` / `$__tags` intact. The committed `datasources/*.yaml` are
the rendered defaults, so `kubectl apply -k .` also works without rendering.

## Apply

```bash
# Whole bundle (recommended)
kubectl apply -k deploy/observability/grafana/

# Or a single file / directory
kubectl apply -f deploy/observability/grafana/datasources/
kubectl apply -f deploy/observability/grafana/dashboards/metl/metl-metrics.yaml

# Dry run / inspect what kustomize builds
kubectl kustomize deploy/observability/grafana/
```

## How the Grafana sidecar picks these up

The kube-prometheus-stack ships Grafana with the `k8s-sidecar` container that
watches ConfigMaps **across namespaces** and provisions them into Grafana:

| What           | Trigger                              | Where it lands                                            |
| -------------- | ------------------------------------ | --------------------------------------------------------- |
| **Datasource** | label `grafana_datasource: "1"`      | Provisioned datasource (matched here by stable `uid`)     |
| **Dashboard**  | label `grafana_dashboard: "1"`       | Imported dashboard                                        |
| **Folder**     | annotation `grafana_folder: "hetu"`  | Every dashboard is filed into the single `hetu` folder    |

So the only "magic" is the label + annotation on the ConfigMap. The dashboard
JSON lives inside `data`; datasources are referenced **by uid** (`prometheus`,
`loki`, `tempo`) so panels keep working regardless of datasource display name.

> Note: depending on your sidecar version the folder annotation may instead be
> `k8s-sidecar-target-directory`. This bundle uses `grafana_folder`, which the
> kube-prometheus-stack default sidecar honours.

## Changing the monitoring namespace / endpoints

All of this now lives in `contract.yaml` — edit it and run `./render.sh`:

- `monitoringNamespace:` — namespace for every ConfigMap **and** the `.svc` URLs.
- `endpoints.{prometheusUrl,lokiUrl,tempoUrl}:` — backend service URLs.
- `datasourceUids:` / `grafanaFolder:` — stable UIDs and the Grafana folder.

`render.sh` rewrites the datasource `metadata.namespace` and `url:` for you, so
`kubectl apply -k .` (or `-f`) just works afterwards.

## Assumptions baked into the default contract — confirm before delivery

- **Loki** is reachable at `http://loki.monitoring.svc:3100`.  ← most likely to differ
- **Tempo** query API is at `http://tempo.monitoring.svc:3200`.
- **Prometheus** is at `http://monitoring-prometheus.monitoring.svc.cluster.local:9090`.
- The METL **traces/events** dashboards use the metrics hetu already emits
  (`cluster_intel_llm_request_*`, `cluster_intel_pod_health_total`). The events
  dashboard also references `kube_event_count` (from kube-state-metrics /
  kube-events-exporter) and falls back to hetu metrics if it is absent.
